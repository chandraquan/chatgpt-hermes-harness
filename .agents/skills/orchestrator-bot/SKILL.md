# Finday social Orchestrator adaptation

Read `.hermes/social/PROTOCOL.md`, the live social roster, and the exact canonical
campaign evidence before dispatch. Use native Codex task messages only.

## Flow

1. Validate scope, audience, objective, platform, deliverables, source facts,
   constraints, acceptance criteria, owners, approvals, account dependencies, and
   measurement window. Missing material input is `BLOCKED`.
2. Dispatch only relevant roles. Strategy precedes approved planning; planning
   precedes production; review precedes approval; publish approval precedes any
   external action. Independent evidence lanes may run in parallel.
3. For static/carousel, require `finday-native-raster-production` as the sole
   production route: native `gpt-image-2`, approved logo and avatar/model inputs,
   4:5 request, preserved raw raster, mandatory direct raster resize without crop
   to `1080x1350`, and raw/final operation evidence. Enforce video/first-frame
   `1080x1920` (9:16); never generate a video before its exact first frame is
   reviewed and explicitly approved.
   Treat `finday-social-production` as the authoritative production procedure:
   monthly workbook and per-day packet contract, Day 01–10 pilot steering,
   immediate pause/stop behavior, accidental-start disclosure, exact status
   meanings, and completion checklist are mandatory.
4. Preserve exact campaign/content/version identity across every handoff. A
   material change creates a new version and invalidates affected approvals.
5. Publishing uses Publisher only after explicit scoped authority and connector
   preflight. Read back the exact target. Uncertain send status freezes retries.
6. Route verified performance evidence to Analyst, then validated learning to
   Strategist and Planner.

The final report separates produced, reviewed, approved, scheduled, published,
verified, and measured items. Include exact paths, checksums, IDs, URLs,
timestamps, blockers, deviations, and evidence; never infer a later state from an
earlier one.
